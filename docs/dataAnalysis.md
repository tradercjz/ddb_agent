

# DDB-Agent: 交互式数据分析手册

欢迎使用 DDB-Agent，您的专属 DolphinDB 智能数据分析伙伴。

本手册将指导您如何通过自然语言，与 Agent 以**协作、交互**的方式完成从数据探索到复杂查询的全部流程，旨在将您的数据分析效率提升到一个新的水平。

## 核心理念：人机协作

与传统的自动化脚本不同，`/sql` 模式的核心是**对话与确认**。Agent 在执行任何可能修改数据或消耗大量资源的查询前，会首先向您展示它的**分析计划**，并等待您的批准。这确保了整个分析过程的准确性、安全性和可控性。

---

## 快速开始：您的第一个分析工作流

让我们通过一个完整的实例，来体验一次典型的端到端数据分析流程。

### 第1步: 开启一个独立的分析会话

为了保持不同分析任务的独立性，我们首先创建一个新的工作会话。

```bash
/session new stock_vwap_analysis
```

> **提示**: 这会创建一个名为 `stock_vwap_analysis` 的新会话。您所有的上下文（表结构、临时文件）和对话历史都将保存在这个会话中，方便您随时切换和回顾。

### 第2步: 加载数据上下文 (`/use`)

这是整个分析流程的**关键前提**。您需要告诉 Agent 您希望分析哪些数据。Agent 会自动加载并理解这些表的结构 (Schema)，为后续的自然语言查询做好准备。



```bash
# 注入 'stock_data' 数据库中的所有表
/use dfs://stock_data

# 或者，只注入单个 'trades' 表
/use dfs://stock_data/trades
```

### 第3步: 开始交互式分析 (`/sql`)

当数据上下文准备就绪，就可以使用 `/sql` 命令来描述您的分析任务了。

#### 示例 1: 数据探索

```bash
/sql 查看一下 trades 表的结构和前5行数据，让我了解下内容。
```

> **Agent 的响应 (提出计划):**
> ```
> [❓ Awaiting Input]
> 我将执行以下计划：
> 1.  调用 `describe_table` 工具来获取 `trades` 表的详细 Schema。
> 2.  执行 SQL 查询 `select top 5 * from loadTable('dfs://stock_data', 'trades')` 来获取示例数据。
>
> 是否批准此计划？
> ```
> **您的回应:**
> ```
> > ok
> ```
> Agent 只有在收到您的肯定答复后，才会执行并返回结果。

#### 示例 2: 复杂分析查询

```bash
/sql 基于 trades 表，计算每只股票每天的成交量加权平均价 (VWAP)。
```

> **Agent 的响应 (提出脚本计划):**
> ```
> [❓ Awaiting Input]
> 我已确认 `trades` 表包含 `trade_date`, `symbol`, `price`, `volume` 列。我计划执行以下 DolphinDB 脚本来计算每日 VWAP。
>
> ```python
> trades = loadTable("dfs://stock_data", "trades")
> daily_vwap = select wavg(price, volume) as vwap from trades group by trade_date, symbol
> daily_vwap
> ```
>
> 是否批准并执行此脚本？
> ```
> **您的回应:**
> ```
> > 看起来不错，执行吧
> ```

### 💡 从中断处继续：永不丢失您的分析进度

**这是 `/sql` 模式最强大的功能之一。**

如果在复杂的分析过程中，任务因为网络波动、长时间执行或您意外关闭终端而被中断，**您不必从头再来**。

**要恢复任务，只需在同一个会话中，再次输入 `/sql` 命令，不带任何参数：**

```bash
/sql
```

Agent 会自动加载上次中断时的状态，并询问您是否从上次失败或中断的步骤继续。这保证了复杂分析任务的连续性和健壮性。

## 高级技巧

### 1. 切换至 `ACT` 模式以实现自动化

在您与 Agent 协作多次，并充分信任其能力后，您可以在 Agent 提出计划时，切换到 `ACT` (执行) 模式，让其自动完成剩余所有步骤，无需每次都请求您的批准。

```bash
# 在 Agent 等待您输入时，发送此命令
/mode act
```
> Agent 会完成当前任务的所有后续步骤，然后在任务结束后自动切回更安全的 `PLAN` 模式。

### 2. 注入外部文件上下文 (`@` 语法)

除了数据库中的表，您还可以将本地文件（如 `.csv`, `.txt`）的内容注入上下文，让 Agent 进行关联分析。

```bash
/sql 实现@/path-to-pdf/指标.pdf 里的因子，并帮我筛选对应的股票。
```

## 数据分析命令速查表

| 命令 | 描述 |
| :--- | :--- |
| `/session new [name]`| **(第一步)** 为您的分析项目创建一个新的、隔离的会话。 |
| `/use [path]`| **(第二步)** 将数据库或表的 Schema 加载到会话上下文中。 |
| `/sql <task>`| **(第三步)** 启动一个交互式、可协作、可恢复的数据分析任务。 |
| `/sql` | **(任务中断后)** 从上次中断的地方恢复您的分析任务。 |
| `@/path/to/file` | 在您的查询中，使用 `@` 符号来引用本地文件，并将其内容注入上下文。 |
| `/context show` | 查看当前会话已经加载了哪些表和文件。 |
| `/context clear` | 清空当前会话的上下文，以便开始新的分析。 |
| `/mode <plan\|act>`| 在 `PLAN` (每次询问) 和 `ACT` (自动执行) 模式之间切换。 |
| `/help`| 显示完整的帮助信息。 |
